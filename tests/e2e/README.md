# E2E-сценарии

```bash
scripts/e2e.sh            # весь набор, ~15 с
scripts/e2e.sh -k grades  # аргументы уходят в pytest
```

Скрипт поднимает одноразовый Postgres той же версии и локали, что в проде, в изолированной сети без выхода
наружу и гоняет тесты в образе бота с кодом, примонтированным только для чтения. Рабочие контейнеры
не затрагиваются. Без `E2E=1` (его ставит скрипт) обычный `pytest tests/` эти сценарии пропускает.

## Как устроено

- **Бот настоящий.** Диспетчер берётся из `bot.main.build_dispatcher()`: те же middleware, роутеры и хуки
  старта, база — настоящий Postgres.
- **Telegram эмулирован** (`harness.py`, `TelegramEmulator`). Эмулятор хранит историю чата и отвечает
  ошибками там, где их вернул бы настоящий Telegram:
  - HTML разбирается как в tdlib;
  - правка без изменений даёт «message is not modified»;
  - проверяются лимит текста 4096 символов, лимит `callback_data` в 64 байта и повторный ответ
    на нажатие кнопки.
- **Пользователь** (`TgUser`) может только то, что может человек: писать и нажимать кнопки, которые
  реально есть на сообщении. Нажатие, оставшееся без ответа, считается ошибкой: в жизни это часики
  на кнопке.
- **«Сегодня» зафиксировано на 15 октября 2026.** Сценарии календаря подставляют свою дату через
  фикстуру `today`: она подменяет `school_today()`, единые часы бота.

## Сценарии

| Файл | Что проверяется |
|---|---|
| `test_e2e_onboarding.py` | меню команд при старте; первый `/start` и стандартные предметы; возвращение со сменой ника; команды до регистрации; `/help` и непонятный ввод; имя с `<`; активность в админке после `/start` |
| `test_e2e_subjects.py` | добавить, переименовать, удалить; дубликат в другом регистре; длина названия; брошенный ввод названия; подсказка при пустом списке; названия с `<`, `_`, `%` |
| `test_e2e_grades.py` | счётчик и прогноз на лету; удаление оценки; «−» на нуле; сброс и отмена; отмена последнего сохранения; счётчик после перезапуска бота; два открытых экрана `/grades`; цвета средних |
| `test_e2e_periods.py` | переход на четверти и ручной выбор периода; повторное нажатие выбранного варианта; автовыбор периода по школьному календарю |
| `test_e2e_summary.py` | средние, рекомендуемые оценки и прогноз на конкретных числах; другой период; повторное нажатие текущего; 20 предметов в лимите сообщения |
| `test_e2e_admin.py` | блокировка и разблокировка, в том числе для уже открытых кнопок; экранирование имён; вход обязателен |
| `test_e2e_school_year.py` | новый учебный год начинается с чистого листа, прошлый виден в сводке; один и тот же триместр разных лет не смешивается; закрепление периода истекает с годом; счётчик и отмена через границу 31 августа / 1 сентября; кнопки старого формата без года |
| `test_e2e_concurrency.py` | двойной `/start`; двойное «Сохранить»; двойное «Отменить последнее сохранение» |
| `test_e2e_deploy.py` | развёртывание с нуля: по README (бот, потом `alembic upgrade head`) и в обычном порядке (миграции, потом бот); схема, как у прода, приводится к моделям; старые оценки получают учебный год по дате |
